> 生成时间：2026-09-19
> 前置：阶段三已收口（75 条验收用例全通过，体验版已上传并分发）
> 关联：`docs/设计方案与开发计划.html` 第 07 节、`cloudfunctions/dishImage/index.js`

## 一、现状：代码已就绪，只差三个环境变量

`cloudfunctions/dishImage/index.js` 已经写好了完整三层逻辑，**不需要改代码就能启用**，缺的只是配置：

| 环境变量 | 含义 | 示例 |
|----------|------|------|
| `IMAGE_API_URL` | OpenAI 兼容的文生图接口地址 | `https://open.bigmodel.cn/api/paas/v4/images/generations` |
| `IMAGE_API_KEY` | 对应 Bearer Token | `sk-xxxx` |
| `IMAGE_API_MODEL` | 可选，默认 `gpt-image-1` | `cogview-4` |

云函数只认这三样，请求体固定为 `{ model, prompt, n: 1, size: '1024x1024' }`，响应支持 `b64_json` 或 `url` 两种返回（给外链时会中转下载再入云存储，避免外链过期）。

未配置时前端会收到 `NOT_CONFIGURED` 并弹「还没配置生图服务」提示——这条已在阶段三用例 E-5 验证通过。

---

## 二、硬约束：不能用 OpenAI 官方接口

**微信云函数运行在境内腾讯云节点，`api.openai.com` 不可达。**所以：

- ❌ `https://api.openai.com/v1/images/generations` —— 连不上，别浪费时间
- ✅ 必须选**境内可直连**且**提供 OpenAI 兼容 `/images/generations`** 的服务

（兼容模式很关键：云函数只发了 OpenAI 格式的请求体，不支持各家自定义 SDK 协议。）

## 三、候选对比（价格为 2026 年公开参考价，以各家官网为准）

| 服务商 | 接口地址（OpenAI 兼容） | 推荐模型 | 参考单价 | 中文理解 | 备注 |
|--------|------------------------|----------|----------|----------|------|
| **智谱 BigModel** | `https://open.bigmodel.cn/api/paas/v4/images/generations` | `cogview-4` | 约 ¥0.02–0.1 / 张 | ⭐⭐⭐⭐⭐ | 中文最强、价格最低、有免费额度 |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1/images/generations` | `black-forest-labs/FLUX.1-dev`、`Z-Image-Turbo` | 约 ¥0.05–0.10 / 张 | ⭐⭐⭐ | 模型种类最多、国内直连、新用户有免费额度 |
| 阿里云百炼（通义万相） | `https://dashscope.aliyuncs.com/compatible-mode/v1/images/generations` | `wanx-v1` / `qwen-image` | 约 ¥0.16–0.20 / 张 | ⭐⭐⭐⭐ | 稳定性与 SLA 最好，企业级 |
| 火山方舟（即梦 Seedream） | `https://ark.cn-beijing.volces.com/api/v3/images/generations` | `doubao-seedream` | 约 ¥0.22 / 张起 | ⭐⭐⭐⭐ | 画质好、价格偏高 |

> 第三方聚合中转平台（各种"统一 Key"网关）**不推荐**：稳定性、商用授权和 SLA 都有风险，且 Key 一旦泄露影响面大。

### 推荐：智谱 BigModel · CogView-4

理由三条：

1. **中文菜名理解最好**——我们的 prompt 是「家常辅食/菜品的手机美食摄影照片：「莲藕消积米糊」」这种中英混排、含具体食材名的描述，中文模型胜出明显。
2. **最便宜**——手动触发模式下一周也就生成几张到十几张，单价 ¥0.02–0.1 意味着**月成本不到一块钱**，试错成本极低。
3. **OpenAI 兼容 + 免费额度**——注册就有额度，可以零成本先跑通再决定要不要充值。

备选：如果 CogView-4 出图风格你不满意（比如偏插画、不够写实），换**硅基流动的 FLUX.1-dev**，写实摄影风格更稳，同样支持 OpenAI 兼容，换一个 `IMAGE_API_URL` + `IMAGE_API_MODEL` 就行。

## 四、接入步骤（全程约 15 分钟）

### 1. 注册并拿 Key

- 打开 <https://open.bigmodel.cn> → 注册登录 → 控制台「API Keys」→ 复制 Key（`sk-` 开头）
- 新用户有免费额度，**先不用充值**，跑通了再说

### 2. 填环境变量

1. 微信开发者工具 → 「云开发」打开控制台
2. 左侧「**云函数**」→ 点 `dishImage`
3. 「**配置**」页签 → 「环境变量」→ 添加：

   ```
   IMAGE_API_URL   = https://open.bigmodel.cn/api/paas/v4/images/generations
   IMAGE_API_KEY   = <你复制的 Key>
   IMAGE_API_MODEL = cogview-4
   ```

4. 保存

### 3. 重新部署（别漏，改了环境变量必须重新部署才生效）

开发者工具左侧文件树 → `cloudfunctions/dishImage` 右键 → **「上传并部署：云端安装依赖」**

### 4. 前端试跑

- 开发者工具「预览」扫码 → 今日页 → 展开某餐 → 点「菜品详情 ›」→ 点「生成配图」
- 首次生成可能要等 20–60 秒（生图 + 上传云存储）

## 五、成本测算（按设计文档「手动触发」模式）

| 项目 | 估算 |
|------|------|
| 触发频率 | 手动，一周 5–15 张（不会到 35 张全生成） |
| 月调用量 | 约 20–60 张 |
| 生图费用 | ¥0.02–0.10 / 张 → **月 ¥0.4–6** |
| 云存储 | 见下方 ⚠️ |

> ⚠️ **容量风险**：设计文档规划的是 WebP / 长边 640px / 单图 40–80KB，但云函数当前**硬编码 `size: '1024x1024'` 且存 PNG**，单图实际约 **1–2 MB**，比规划大了 20 倍。云开发免费/基础套餐的存储与数据库共享 2GB，按 100 张算就是 100–200MB，占掉 5%–10%。详见第七节 P-2。

## 七、本次发现的问题（接入前建议一并处理）

| 编号 | 问题 | 依据 | 建议 | 优先级 |
|------|------|------|------|--------|
| P-1 | **内容安全未做**：AI 生成图片直接入云存储并展示，个人小程序对 AI 生成内容有合规要求，设计方案第 07 节也提到「需要内容安全机制」 | 设计文档 07 节 vs `dishImage/index.js` | 低频手动触发风险可控，但建议至少保留生成记录（当前 `prompt/model/generatedAt` 已落库，可追溯）；若后续开放自动批量生成，必须先接图片内容安全检测 | P1（延后） |
| P-2 | **图片规格偏离设计**：硬编码 `size: '1024x1024'`、存 PNG，设计文档要求 WebP / 640px / 40–80KB | 设计文档 07 节「图片规格与容量」 | 改 `size` 为 `640x640`（或各家支持的尺寸写法），并在上传前压缩/转码；或接受现状但留意 2GB 容量 | P2 |
| P-3 | **尺寸参数不通用**：各家对 size 的写法不同（如通义万相用 `1024*1024`），当前硬编码 OpenAI 写法 | 各家 API 文档 | 换服务商时若报错，先看是否是 size 格式问题 | P3 |
| P-4 | **`hitCount` 未实现**：设计文档要求图库命中后 `hitCount + 1` 用于统计「哪些菜最常吃」 | 设计文档 07 节一层 | 属二期候选，暂不阻塞 | P3 |

## 八、风险关注点

1. **Key 安全**：Key 放在云函数环境变量里是正确的（不进代码库、不进小程序包），但**别提交到 GitHub**——`cloudfunctions/dishImage/index.js` 里不要硬编码任何 Key。
2. **出网依赖**：配图功能依赖第三方接口可用性，接口挂了只影响「生成」，不影响已有配图展示（`resolve` 走数据库）——这个降级设计是对的。
3. **额度告警**：建议在服务商后台设置余额告警，避免免费额度用完后静默失败（表现为一直弹「还没配置生图服务」以外的错误提示）。
4. **合规**：个人小程序涉及 AI 生成内容，正式发布时审核可能问及；保留手动触发 + 生成记录可追溯是当前最稳的姿态。
